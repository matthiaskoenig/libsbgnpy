# Release notes for libsbgnpy 0.6.5

This release contains the changes of 0.6.4, which was tagged but not published: the release workflow pinned the PyPI publish action to a commit without a container image. 0.6.5 is the first release with these changes on PyPI.

## Fixed

- Text in mixed content, e.g., `<p>A <b>bold</b> word</p>` in XHTML notes, is no longer lost when a document is written or when `element_to_string` serializes a note; mixed content is no longer indented.
- A document whose root is no SBGN-ML `sbgn` element raises a `ParserError` instead of being read as an empty `Sbgn`; a document missing a required element raises a `ParserError` instead of a `TypeError`.
- Files are decoded with the encoding of their XML declaration (e.g., `ISO-8859-1`) in `read_sbgn_from_file` and `validate_xsd`; `read_sbgn_from_string` ignores the declared encoding of the already decoded string.
- `upconvert` only moves element and attribute names from the SBGN-ML 0.1 and 0.2 namespaces, text and attribute values mentioning a namespace are left as they are; the validation errors of upconverted documents keep the lines of the file.
- `read_render_from_extension` finds the render information by its qualified name, an entry merely mentioning `renderInformation` no longer raises; render information of the earlier EML render extension is upconverted, so the render information of `neuronal_muscle_signalling_color.sbgn` can be read.
- `render_sbgn` checks the answer of the web service and raises the new `RenderError` (a `requests.RequestException`) if it is no image, e.g., the html page of a proxy, or larger than 50 MB; the image is written atomically and the suffix is checked in any case.

## Changed

- Documents are parsed with an explicitly hardened parser (no entity resolution, no network access) by the new `parse_xml`; `upconvert_tree` upconverts a parsed tree. `upconvert` raises an `lxml.etree.XMLSyntaxError` for a string which is no XML.
- The package ships a `py.typed` marker, so type checkers use its annotations.
- The docstrings of `libsbgnpy.sbgn` are plain google style text instead of the namespace prefixed html of the schema.

## Known issues

- The rendering web service currently returns a JPEG although it declares a PNG. `render_sbgn` writes the image as it is and logs a warning.

## Development

- The PyPI publish action of the release workflow is pinned to the commit of v1.14.2.
- The bindings are regenerated with xsdata 26.2 by `scripts/generate_bindings.py`, which applies every fix to the generated code; `tests/test_bindings.py` fails if the committed bindings are outdated.
- The tests querying the rendering web service are marked as `network` and deselected by default (`pytest -m network`), `render_sbgn` is tested against a local HTTP server.
- The source distribution only contains what is needed to build, test and document the package (1.7 MB instead of 8.4 MB).
- The `ty` check of tox uses the versions of `uv.lock`; the release workflow checks that the tag equals the package version, builds with `uv build` and pins the PyPI publish action to a commit.
- The citation information carries the DOI of 0.6.3.
- Update development dependencies: ty 0.0.83, tox 4.64.1, Zensical 0.0.64 and mkdocstrings-python 2.0.9; the workflows use `setup-uv` 10.2.0.
