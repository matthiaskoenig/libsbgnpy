# Release notes for libsbgnpy 0.6.0
![libsbgnpy](https://github.com/matthiaskoenig/libsbgnpy/raw/develop/docs/images/libsbgnpy.png)

We are pleased to release the next version of libsbgnpy including the following changes. This is a large release which reorganizes the package, so it starts with what has to be changed in existing code.

## Breaking changes
- python 3.10 support dropped, python >=3.11 is now required
- the examples moved out of the package to `examples/` in the repository and the `_example` suffix is gone, so `libsbgnpy.examples` and `libsbgnpy.sbgn_examples_dir` are no longer part of the package. They run as scripts from a checkout, e.g., `python examples/read.py` instead of `python -m libsbgnpy.examples.read_example`, and the example SBGN files are no longer shipped in the distribution. A `validate` example was added, the `info` example was merged into `read`
- `validate_xsd` returns the validation errors as a list of strings, which is empty for a valid document, instead of returning the lxml error log or `None` and writing to stderr: `if validate_xsd(f) is None` becomes `if not validate_xsd(f)`. It no longer prints, it logs a summary
- the dead `Issue` and `Severity` classes were removed from `libsbgnpy.validator`. They described the result of a schematron validation which was never performed
- importing `libsbgnpy` no longer calls `rich.pretty.install()`, i.e., it does not replace the `displayhook` of the interpreter any more. Install the rich representations explicitly if you want them
- `libsbgnpy` no longer configures logging: it adds no handlers and sets no levels, so messages are formatted and filtered by the application. `log.enable_rich_logging()` turns the rich output on for scripts and examples
- the unfinished mapping of SBO terms to SBGN glyphs moved from `libsbgnpy.sbo` to `libsbgnpy.oven`, which collects work in progress and is not shipped in the release
- minimum versions of the dependencies raised to `lxml>=6.1.3`, `requests>=2.34.2`, `rich>=15.0.0` and `xsdata>=26.2`; the direct dependency on `urllib3` was dropped, it is a dependency of `requests`

## Features
- `read_sbgn_from_string` added, the counterpart of `write_sbgn_to_string`, and `upconvert` is part of the module API, so SBGN-ML 0.1 and 0.2 documents can be converted without reading them
- notes and extensions can be read back: `element_to_string` serializes an entry of a `notes` or `extension` element, which is read as an element tree, back to XML, and `element_from_string` is its counterpart
- `read_render_from_extension` returns the render information stored in the extension of a map, which previously had to be assembled by hand from the parsed elements

## Fixes
- fix the corruption of escaped characters when a document is written: the serialized document was unescaped as a whole to write the raw XML of the `notes` and `extension` elements as markup, which also unescaped the labels, so a label such as `a < b` produced a document which could not be read again. The raw XML is parsed into element trees before serialization now, the document which is passed in is not modified
- fix writing more than one entry in a `notes` or `extension` element: only the first one ended up inside the element, the others were written after it
- fix `read_sbgn_from_file` raising an `UnboundLocalError` instead of the parse error when a file could not be parsed
- fix the validation of SBGN files (#60): documents in the SBGN-ML 0.1 and 0.2 namespaces are upconverted before they are validated, as they are when they are read, so they validate against the packaged 0.3 schema instead of failing on the namespace. All 63 documents of the test corpus validate now, and the validation tests are no longer skipped
- fix the ids the arcs of the ethanol example refer to, three arcs pointed at glyphs which did not exist
- the rendering web service is queried with a timeout, so a request cannot hang forever, and the file handle of the uploaded document is closed

## Documentation
- documentation migrated from mkdocs to [Zensical](https://zensical.org/), the static site generator of the Material for MkDocs authors: markdown sources in `docs/`, configured in `zensical.toml`, with the API reference rendered from the docstrings by mkdocstrings. Nothing rendered is committed any more, the site is built and published to https://matthiaskoenig.github.io/libsbgnpy by a GitHub workflow on every change
- new user guide with a page per topic: the object model of an SBGN map, reading and writing, notes and extensions, render information, validation and images. The jupyter notebook of the examples was replaced by these pages
- API reference extended from a single page to eight modules, covering the generated bindings of the SBGN and the render schema, io, validation, image rendering, the console and logging. All docstrings converted to google style, so arguments, return values and errors are rendered instead of appearing as raw text
- `llms.txt`, `llms-full.txt` and the markdown of every page are generated into the site, so agents and language models read the documentation as markdown
- the README is lean and points at the documentation
- the four SBGN specification PDFs are no longer vendored in `docs/`, they are published with the [SBGN specifications](https://github.com/sbgn/sbgn/wiki/SBGN_Specifications)
- `CITATION.cff` added and the Zenodo metadata updated with the current affiliation and a description of what the package does

## Development
- mypy replaced by ty for type checking; ty runs in CI, in `tox r -e ty` and as a pre-commit hook, with `error-on-warning`, so the tree stays free of diagnostics
- more ruff rules (import sorting, docstrings, pyupgrade, bugbear, comprehensions, simplifications, returns, logging format) and additional pre-commit hooks (toml, json, case conflicts, line endings, forgotten debug statements); the configuration moved from `ruff.toml` to `.ruff.toml`
- github actions reworked into the `ci-cd`, `ruff`, `ty` and `documentation` workflows, with least privilege permissions, concurrency groups, timeouts and pinned actions, and a dependabot configuration for the actions and the python dependencies. The release job builds with hatch and publishes to pypi with trusted publishing
- the project urls reach the metadata now: the table was written as `[project_urls]` instead of `[project.urls]`, so it was silently ignored and the pypi page carried no links at all. `Documentation` points to the documentation site and a `Changelog` url was added. The license metadata follows PEP 639, i.e., `license = "MIT"` with `license-files`, instead of the deprecated `License ::` classifier
- root configuration cleaned up: the `docs` and `test` extras merged into `dev`, the pytest configuration moved to `[tool.pytest.ini_options]` in `pyproject.toml`, the unused `pytest-raises` dependency and the `install` tox environment are gone, `MANIFEST.in` was removed, which hatchling does not use, and `.gitignore` lost the entries of tools which are not used
- the test corpus moved from `tests/test-files` to `tests/data` and every document of it is read, written and validated; the skipped notes, extension and render tests are unskipped, and every example is run by the test suite
- the generated bindings carry a module docstring and the manual fixes which are applied after a regeneration are documented in `src/libsbgnpy/schema/README.md`
